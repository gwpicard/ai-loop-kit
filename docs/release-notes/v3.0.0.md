# AI Loop Kit 3.0.0

This release changes what each project holds: loop settings move from `AGENTS.md` into a committed `loop.json`, and `PLAN.md` is no longer part of the kit. Setup moves the settings and keeps the contents of `PLAN.md` in an inbox issue for you to place. A project with kit 1.x runtime files or a `.lite/` folder must first run the 2.2.2 setup.

Every project gets these changes, and every existing project needs one setup run before the loop will start again. The loop refuses to run until `loop.json` exists. 

## Updating

1. In Claude Code, refresh the marketplace, then update the plugin:

       /plugin marketplace update ai-loop-kit
       /plugin update ai-loop-kit@ai-loop-kit

2. Start a new Claude Code session so that the new plugin loads.
3. In the commands below, `<plugin>` is the installed plugin folder, the one that holds `bin/`. A loop that is already running keeps the version it started with, and it cannot read `loop.json`. Stop it from the project root, then wait until `.loop/loop.pid` is gone:

       <plugin>/bin/loop stop

4. Run setup from the project root. Preview it first with `--dry-run`, which prints each change and makes none, then run it for real:

       python3 <plugin>/scripts/setup.py --dry-run
       python3 <plugin>/scripts/setup.py

5. Place the contents of `PLAN.md` before you restart. Setup files an inbox issue titled "Find a home for the contents of PLAN.md". The kit no longer reads `PLAN.md`, so its decisions, product rules and stops reach sessions only after you move them: standing rules and project stops into `AGENTS.md`, decisions into the issues they bind, and red-team surfaces into the `Red-team surfaces` list in `loop.json`. With an empty list, the end-of-loop pass proposes surfaces in an inbox issue.
6. If `loop.json` holds a `Protected paths` list, add `"loop.json"` and `"loop.local.json"` to it, keeping its entries. A list you set replaces the defaults, and setup does not add these two files to it.
7. Commit `loop.json`, `AGENTS.md`, `.gitignore` and any files from step 5 through a pull request, merge it, and update your checkout. For example, with `<default branch>` standing for your project's default branch:

       git switch -c loop-settings
       git add loop.json AGENTS.md .gitignore
       git commit -m "Move loop settings to loop.json"
       git push -u origin loop-settings
       gh pr create --base <default branch>

   The loop reads `loop.json` from your checkout, but sessions read `AGENTS.md` from the loop branch, which takes in the default branch only when the loop drains. To give sessions the new `AGENTS.md` at once, merge the default branch into the loop branch (`loop/main` unless you set another) before you restart.
8. Start the loop from the project root:

       mkdir -p .loop && nohup <plugin>/bin/loop run > .loop/loop.out 2>&1 &

Setup does the following, and it prints each change before it makes it:

- It moves the settings under `## Loop` in `AGENTS.md` into a new `loop.json`, and removes that section from `AGENTS.md`. Lists, numbers and the four role settings are written as JSON values. A `Builder model` or `Reviewer model` line becomes `Builder`, `Test writer`, `Reviewer` and `Pass` settings that use the `claude` agent with that model. The `Defect rounds` line is dropped, as it has been unused since 2.2.0. If a setting under `## Loop` is not recognised or has the wrong type, setup refuses, names it and does not write `loop.json`.
- It adds `loop.local.json` to `.gitignore`, and `.loop/` if that is missing.
- It files one inbox issue titled "Find a home for the contents of PLAN.md". The issue holds every non-empty section of `PLAN.md` with a proposed home for it. Setup leaves `PLAN.md` in place and does not file the issue a second time.
- It renames the heading `## Paths the builder may change` to `## Protected paths this issue may change` in every open issue, and saves each original body under `.loop/migrations/`. Closed issues are not edited.
- It records each change, with how to undo it, in `.loop/migrations.log`.
- It warns when `AGENTS.md` and `CLAUDE.md` together hold more than 1,500 words, not counting a line that only imports `AGENTS.md`. The warning changes nothing.

A real run then creates any missing labels, loop branch and pinned `Factory` issue, as before, and runs your Test command on a fresh checkout of the loop branch. Running setup again is safe: it adds only what is missing.

Per-machine settings go in `loop.local.json`, which setup adds to `.gitignore`. It accepts only `Parallel` and `Idle hours`, and refuses any other key. For example:

    {"Parallel": 3}

Both files are read again at the start of every loop cycle. If either one cannot be read or validated, the loop keeps the previous settings and logs the error once.

If your project is on kit 1.x, or on kit 2.0 with a `.lite/` folder, 3.0.0 no longer moves those files. Setup and `loop run` refuse and print `next: install kit 2.2.0, run its setup, then update to this version.` Any 2.2 release includes those moves:

1. Stop the running loop with its own version's stop command, and wait until its `loop.pid` is gone. For kit 2.0, that is `.lite/loop.pid`.
2. For a kit 1.x project, add a `## Loop` section to `AGENTS.md` with your test command, which the 2.2.2 setup requires:

       ## Loop
       Test command: <the command that runs your tests>

3. Run the 2.2.2 setup from the project root:

       git clone --depth 1 --branch v2.2.2 https://github.com/gwpicard/ai-loop-kit.git ../ai-loop-kit-2.2.2
       python3 ../ai-loop-kit-2.2.2/kit/scripts/setup.py

4. After it succeeds, move any remaining `.lite/` folder, with all its contents, to an unused backup path outside the project, then follow the steps above.

## What changes

1. **Settings live in `loop.json`.** The committed `loop.json` is a JSON object, and only `Test command` is required. Unknown keys and values of the wrong type are refused, and the refusal names the file and the key. Both `loop.json` and `loop.local.json` are among the default protected paths, so a piece that changes one must name it under `## Protected paths this issue may change`; a `Protected paths` list you set replaces the defaults, as step 6 above explains. Each build keeps the settings it started with, so an edit during a build does not change that build's checks. Before this release, the settings were prose lines under `## Loop` in `AGENTS.md`.
2. **`PLAN.md` is no longer part of the kit.** Decisions go in the issue that needs them, and a builder records its own in the DEVIATIONS block of its reply. Standing rules go in `AGENTS.md`. The kit's own list of stops moved into the sessions' shared instructions. Sessions are told to park only for a choice that changes what the product does or looks like, or what ships, or when one of the stops applies, and to decide everything else and record it. That rule is an instruction to the model and no code enforces it. The end-of-loop pass reads the `Red-team surfaces` list in `loop.json` and files each proposed lesson as its own inbox issue, where it used to group them in its findings issue. Builders and test writers no longer append to `PLAN.md`. The final pull request lists the deviations from each merged issue's build note under "Decisions to confirm". Its hands-on section opens with the loop branch and commit, and no longer reads a "Try it" section.
3. **The permissions section of an issue is renamed.** The section that lists protected paths a builder may change is now `## Protected paths this issue may change`. The old heading grants nothing. The shape skill and the issue template use the new name, and setup renames it in open issues, as described above.
4. **Old runtime layouts are refused.** Setup no longer moves kit 1.x files into `.loop/v1/` or a `.lite/` folder into `.loop/`. It refuses, leaves every file where it is and gives the upgrade advice above. This removes the code that handled those two layouts.
5. **Builder tests are checked against the loop branch before review.** When a `Test files command` is set and an issue changes both non-test files and test modules outside the test writer's locked tests, the loop restores the non-test files to the branch base in a scratch copy and runs each of those test modules. The reviewer's prompt lists the tests that still pass without the change, and the reviewer is instructed to ask for changes for each unless the builder's DEVIATIONS explain why it guards behaviour that already existed. Each check is recorded as a `revert-check` event.
6. **The squash commit can carry a sign-off or agent co-author lines.** Two settings in `loop.json`, both off by default, take `true` or `false`. `"Sign-off": true` ends the squash commit message with one `Signed-off-by:` line built from the project's git `user.name` and `user.email`. `"Agent attribution": true` keeps the agents' co-author lines, which the loop otherwise removes. These two settings are not accepted in `loop.local.json`.
7. **Setup warns when standing instructions are long.** It counts the words in `AGENTS.md` and `CLAUDE.md` together and warns above 1,500, naming each file's count. It edits neither file.
8. **A shorter design document and Mac advice.** `docs/DESIGN.md` is rewritten to describe the kit as it now is, at about 2,100 words where it had about 5,200. `kit/README.md` explains how to stop Spotlight on a Mac from indexing the loop's worktrees, which can compete with builds for the processor: add the folder that holds your projects and `.loop-worktrees` to System Settings, Spotlight, Search Privacy.

## What was tested

All 954 tests in the kit's suite pass. Each change has tests that fail without it, including the migrations in setup: the move of `## Loop` into `loop.json` with a preview, the inbox issue for `PLAN.md`, the heading rename with saved bodies and undo records, and the refusal of old layouts with every file left in place.

Not proven yet: these tests run setup against a fake `gh` command, not against a live GitHub repository, and no full loop run on a migrated project has been recorded for this release. The first project to migrate and run is the measure.
