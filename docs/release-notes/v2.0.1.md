# AI Loop Kit 2.0.1

This release keeps the loop's runtime files in `.loop/`, as in 1.x, moves older files there for you, and adds a setup skill so that asking Claude to set up the loop works in a new project.

Every project that runs 2.0.0 needs the steps below. Its `.lite/` folder moves into `.loop/` the first time setup runs or the loop starts.

## Updating

1. Before you update, stop any running loop with the 2.0.0 plugin, from the project root:

       <plugin>/bin/loop stop

   Wait until `.lite/loop.pid` is gone. The stop command of 2.0.1 cannot stop a 2.0.0 loop, because the two look for the stop file in different folders. If you have already updated, run this from the project root instead:

       touch .lite/stop

   The move into `.loop/` refuses while a 2.0.0 loop is still running.
2. In Claude Code, refresh the marketplace, then update the plugin:

       /plugin marketplace update ai-loop-kit
       /plugin update ai-loop-kit@ai-loop-kit

3. Start a new Claude Code session so that the new plugin loads.
4. In each project, before you start the loop, ask Claude to set up the loop, or run this from the project root:

       python3 <plugin>/scripts/setup.py

   Setup moves the older runtime files into `.loop/` and adds a `.loop/` line to `.gitignore`. Commit that line yourself; you can remove the `.lite/` line in the same commit.

Setup moves your runtime files and does not change them. It deletes nothing except an emptied `.lite/` folder.

## What changes

1. **The runtime folder is `.loop/` again.** Version 2.0.0 kept the loop's lock, logs and state in `.lite/`, a working name left over from the rewrite, so a project that had used 1.x ended up with both folders. Every path now uses `.loop/`, and the environment variables the loop sets for its sessions change from `LITE_*` to `LOOP_*`. The command to start the loop becomes:

       mkdir -p .loop && nohup <plugin>/bin/loop run > .loop/loop.out 2>&1 &

2. **Older runtime files move into `.loop/` by themselves.** Setup and every loop start do this first:
   - If `.loop/` holds files that only kit 1.x wrote, such as `heartbeat` or `dashboard.json`, everything in it moves into `.loop/v1/`. Version 2 does not read that folder.
   - The contents of `.lite/` move into `.loop/`. A folder in both, such as `logs/`, is merged. A file whose name `.loop/` already has moves in beside it as `<name>.lite`, for example `loop.out.lite`.
   - Nothing moves while a loop runs from `.loop/`, and the move refuses while a 2.0.0 loop runs from `.lite/`. A file that cannot be moved ends in a `refused:` line with the next step.

3. **A setup skill.** In 2.0.0, a request to set up the loop had no skill behind it, so a first install in a new project found nothing to run. The new setup skill reads `AGENTS.md`, proposes the `## Loop` lines from the project (for example a `Makefile` target or `package.json` scripts) and asks you to confirm them. It then tells you what setup will create on GitHub, asks before it runs, runs setup and reports each line. The loop skill now only starts, stops and watches the loop.

4. **Log clean-up removes only the loop's own logs.** When the loop exits it deletes logs older than 14 days. It used to delete every file in the logs folder, which in `.loop/logs` would have included the logs of kit 1.x. It now deletes only the files the loop itself names.

## What was tested

The kit's suite of 316 tests passes on macOS and Ubuntu, and `tests/run-all.sh` passes with the repository's house rules. New tests cover moving 1.x files and `.lite/` into `.loop/`, a second run that changes nothing, a name already in `.loop/`, a merged folder, the start command's output left in place, a refusal while a 2.0.0 loop runs, a running loop whose files stay in place, a file in the way, and a log clean-up that keeps a 1.x log.

Not proven yet: the move has not run on a real project; the first will be the next start on the trial project. Worktrees that a 2.0.0 run left in a `.lite-worktrees` folder beside the project are not moved; the loop lists any it finds as left behind when it exits.
