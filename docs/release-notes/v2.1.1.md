# AI Loop Kit 2.1.1

This release fixes the start check for Codex roles. In 2.1.0 the check refused codex-cli 0.166.0 even though its help text lists every flag the kit passes. It no longer does.

Only projects that set a role to `codex` in `AGENTS.md` are affected. Projects that use Claude for every role behave exactly as in 2.1.0.

## Updating

1. In Claude Code, refresh the marketplace, then update the plugin:

       /plugin marketplace update ai-loop-kit
       /plugin update ai-loop-kit@ai-loop-kit

2. Start a new Claude Code session so that the new plugin loads.
3. A loop that is already running keeps the version it started with. To move it to 2.1.1, stop it from the project root, wait until `.loop/loop.pid` is gone, and start it again:

       <plugin>/bin/loop stop
       mkdir -p .loop && nohup <plugin>/bin/loop run > .loop/loop.out 2>&1 &

If the loop refused to start under 2.1.0, there is nothing to stop: start it with the second command.

No settings change is needed, and the update does not touch the files in `.loop/`.

## What changes

**The Codex start check accepts short flags written with a comma.** Before a loop or setup runs a role on Codex, the kit reads `codex exec --help` and `codex exec resume --help` to confirm that it lists the flags the kit passes. In 2.1.0 it split that text on whitespace and looked for each flag as a whole word. codex-cli 0.166.0 prints a short flag together with its long form, as in `-s, --sandbox <SANDBOX_MODE>`, so the check saw `-s,` rather than `-s` and refused with a message such as:

    Builder, Test writer set to codex, but `codex exec` has no -s flag

The check now collects each word that starts with one or two hyphens followed by a letter, so a trailing comma is no longer part of the flag. A flag that appears only inside a longer one, such as `-o` inside `--oss`, still does not count, and a Codex that lacks one of the flags is still refused, with the flag named.

## What was tested

All 675 tests in the kit's suite pass on macOS. New tests feed the check help text in the comma form and confirm that it is accepted, that each missing flag is still refused by name, and that a flag inside a longer word is not counted. The fixed check was also run against codex-cli 0.166.0 on macOS with every role set to `codex`, and the check reported no refusal.

Not proven yet: no loop with a Codex role has run on 2.1.1.
