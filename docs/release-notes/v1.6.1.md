# AI Loop Kit 1.6.1

AI Loop Kit 1.6.1 fixes problems that appeared when 1.6.0 was used on real projects. Runs recover more often from their own faults, and a re-run no longer mistakes earlier build code for work that is already done.

**Who gets what.** Every change reaches every project, with four exceptions. The `- Unconfirmed:` line applies only to projects that use the researcher, which is still a preview. The resume step, which judges an earlier build before building again, applies only to pieces whose checks are all tests; pieces with a goal or gauntlet check build as before. The longer-prompt fix matters on Linux. The exemption for files the Test command creates, and the new ready warnings, apply only to pieces made ready after the update.

## Updating

1. Update the plugin, either from a terminal:

   ```text
   claude plugin update ai-loop-kit@ai-loop-kit
   ```

   or in Claude Code: run `/plugin`, open the **Installed** tab, select **ai-loop-kit** and choose **Update now**.

2. Run `/reload-plugins`, or start a new session, so Claude Code loads the new version.

No other action is needed. If you are updating from a version before 1.6.0, read the 1.6.0 notes first: they ask you to install uv. Your issues, pieces and loop settings stay as they are. The ready record of an existing piece is not rewritten, but the changes that act while a run builds, such as the comparison with the base, apply to it.

## What changes

1. **Run faults return the piece to ready.** When an unexpected error after the piece was claimed, a run that died, or a usage limit that outlasts one wait leaves a piece in building, the piece now goes back to ready instead of to shaping. A new `requeue` move does this, at most twice since the piece last became ready. The hand-back records carry two new causes, `run-error` and `dead-run`; a usage limit keeps its cause, `usage-limit`. A run that was stopped and restarted recovers its piece to ready in the same way.

   When the next run finds an earlier build and the base brought nothing new, it judges that build first, for pieces whose checks are all tests. If it passes, the run makes no builder attempt and goes straight to review. If it fails, the builder starts from it and is given the failure.

   Every other hand-back, such as an idle builder, a stop request or a dirty build folder, still goes to shaping. So does a refusal after the piece was claimed, because it needs a person. A failed pull request after submit also goes to shaping: the piece is already in approval and the only way out is `reject`.

2. **Earlier build code is no longer mistaken for shaping work.** Ready used to record a branch tip that already held build code as the bar, so the next run reported the piece as already satisfied. The kit now tells earlier build code apart by comparing the piece branch with the base. Ready warns when the piece branch holds earlier build code and says that the next build starts from it. The review diff now starts at the merge base with the base branch and leaves out the judge files.

3. **A piece can be shaped again while a clean build folder exists.** A clean build folder is now released when a piece goes back to shaping, so re-shaping is no longer blocked by a build folder that holds the piece branch. The shape skill pulls the piece branch only when it exists on the remote, and tells you to run `gate.py doctor` if a build folder still holds the branch.

4. **Files the Test command creates no longer fail the next run.** Ready records the paths the Test command creates, such as caches and reports. The run leaves them out of the dirty-folder check, and submit refuses a change that adds one. When the dirty files look like reports or caches, the dirty-folder message suggests adding them to `.gitignore` on the base branch.

5. **Long prompts start on Linux.** Linux refuses a single command-line argument over 128 KB, so a reviewer prompt with a large frozen baseline failed to start with "Argument list too long". Every Claude and Codex session now receives its prompt on standard input.

6. **The builder stops when the Approach breaks a test.** If following the Approach would break an existing test or a `(stays)` item, the builder stops with `spec-unclear` and does not choose a way round it. Shaping now searches for existing tests that the new spec would break, and `kit/spec-format.md` has a new section, "Change an earlier test": list the test file under `Files:` in the Exit section, and only the changed test takes the new piece's Contract ID.

7. **Check settings and lockfiles.** Ready now warns when the Approach names a check-settings file, which it previously caught only in the Contract and the Exit files. Lockfiles no longer count towards the 1,000-line rule, so they do not need `Large file:`. A judge at the project root now freezes only `conftest.py` and the root files whose names start with the judge file's name without its extension, so `README.md` and `package.json` are no longer frozen with it. A judge in a subfolder still freezes its whole folder.

8. **Smaller corrections.**
   - The researcher can mark a finding it could not confirm with a `- Unconfirmed: <fact>` line. The kit sets such lines aside; before, any note outside the finding format made it refuse all the findings. Shaping takes each such line to you instead of writing it into `## Research`. A line the kit cannot read is refused with that line named.
   - A failed `gh` call now shows its first line instead of a whole error page. Authentication errors keep their full text.
   - `gate.py sync` now closes an open issue that carries the done label.

## What we tested, and what is not proven yet

- All of the kit's own checks pass on Linux and macOS. The changes above have new or updated tests, except the dirty-folder hint and the shape skill's remote-branch rule.
- The prompt change was tested with a 200,004-byte prompt to fake Claude and Codex sessions, and by checking that the prompt is not in the arguments.
- Not proven yet: a run against a real project with these changes; a real Claude or Codex session with a prompt over 128 KB on Linux; the resume step for pieces with a goal or gauntlet check; and a usage limit that outlasts one wait, against a real limit; and a failed pull request after submit, which still goes to shaping.
