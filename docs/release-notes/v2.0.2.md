# AI Loop Kit 2.0.2

On macOS, this release makes the loop wait before it starts a session or a test command while the system reports memory pressure, so the loop does not start new work while the Mac reports memory pressure.

The change applies on macOS only. On Linux the loop behaves as in 2.0.1. The kit does not run natively on Windows.

## Updating

1. In Claude Code, refresh the marketplace, then update the plugin:

       /plugin marketplace update ai-loop-kit
       /plugin update ai-loop-kit@ai-loop-kit

2. Start a new Claude Code session so that the new plugin loads.
3. A loop that is already running keeps the version it started with. To move it to 2.0.2, stop it from the project root, wait until `.loop/loop.pid` is gone, and start it again:

       <plugin>/bin/loop stop
       mkdir -p .loop && nohup <plugin>/bin/loop run > .loop/loop.out 2>&1 &

No settings change is needed, and the update does not touch the files in `.loop/`.

## What changes

1. **Sessions and test commands wait while memory is under pressure.** The loop reads the macOS memory-pressure level before it starts an agent session and before each Prepare, Test or Check command, whether run by the Stop hook, before a merge or on the loop branch. While the level is warning or critical, it waits and reads it again every 30 seconds, then starts the work once the level is back to normal. A wait prints a line when it begins, repeats that line every ten minutes while it lasts, and prints the wait's duration when it ends. A wait before a session appears in `.loop/loop.out`, or in the build's log in `.loop/logs/` when `Parallel` is above 1. A wait before a merge or a loop branch test appears in `.loop/loop.out`. A wait before a command the Stop hook runs is printed inside the agent session, where you will not normally see it.

   Waiting does not count toward a session's time limit or a command's timeout. Because the level belongs to the whole machine, several loops on one Mac all wait while it is high.

   The reason: in a long run on a 16 GB Mac, sessions and overlapping test runs from the loop, on top of a browser and other Claude Code sessions, filled memory and swap until macOS stopped responding and restarted, four times in one evening. The loop had started each piece of that work without any check.

2. **The Stop hook waits at most 10 minutes.** A test command run by the Stop hook at the end of a session waits for memory pressure to ease for up to 10 minutes, then runs anyway, so that the wait and the command fit within the hook's 30-minute limit.

3. **A further build checks memory pressure.** The loop already held back every build after the first while the load average was at or above the number of CPUs, or while free plus inactive memory was below 1.5 GB. The memory part now uses the memory-pressure level instead. In the run above, free plus inactive memory measured 1.59 GB while swap was 93% full, so the old check let more work start.

## What was tested

The kit's suite of 327 tests passes on macOS, and `tests/run-all.sh` passes with the repository's house rules. New tests replace the memory-pressure reading with a stub and check that a session and a command are held while the level reads warning and start once it reads normal; they also cover no wait when the level cannot be read, the Stop hook's 10-minute limit, and the check before a further build.

Not proven yet: the memory-pressure level has not been observed at warning or critical during a real run, so no real run has shown a wait. A wait holds back new work; it does not free memory that running sessions and other applications already hold.
