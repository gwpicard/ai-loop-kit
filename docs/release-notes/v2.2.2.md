# AI Loop Kit 2.2.2

This release removes four causes of needless parks and drains found in a real run of 2.2.1: drains while a chain of issues waited on a parked one, a yes that granted nothing, searches refused as commands, and stops found only at merge.

Every project gets these changes.

## Updating

1. In Claude Code, refresh the marketplace, then update the plugin:

       /plugin marketplace update ai-loop-kit
       /plugin update ai-loop-kit@ai-loop-kit

2. Start a new Claude Code session so that the new plugin loads.
3. In the commands below, `<plugin>` is the installed plugin folder, the one that holds `bin/`. A loop that is already running keeps the version it started with. To move it to 2.2.2, stop it from the project root, wait until `.loop/loop.pid` is gone, and start it again:

       <plugin>/bin/loop stop
       mkdir -p .loop && nohup <plugin>/bin/loop run > .loop/loop.out 2>&1 &

This release needs no setup run. Settings, labels, parked issues, the loop branch and its pull requests carry over unchanged.

## What changes

1. **No drain while a chain of issues waits on a parked one.** 2.2.1 held the drain only when each `ready` issue depended directly on the parked issue. When the queue was a chain, such as one issue depending on another that depended on the parked one, the loop drained anyway: four times in one afternoon, about 20 minutes each, with replies read only afterwards. The loop now follows dependencies through other `ready` issues: when every `ready` issue is blocked by a parked issue, directly or through others, it holds the drain until an hour after the latest park, as 2.2.1 does for direct dependencies. A build that parks also counts as parked in the same cycle.
2. **A yes approves the test files the question names, whatever its wording.** In 2.2.1 a yes approved files only when the question used one of a few verbs, so "Allow updating …" or "May the builder replace …" approved nothing and the issue parked again. Now any question that ends with a question mark and names test files is approved by a clear yes. Files named only in the recommendation still do not count, and a protected path is never approved.
3. **Searches are no longer refused for mentioning git or `gh`.** In builder, test-writer, reviewer and pass sessions, quoted arguments and heredoc bodies no longer trigger the rule against git commands and `gh` merely by mentioning them. The rules that apply in every session, such as no push to the default branch, still read the whole command. A reviewer's `rg 'gh\(' kit` or a test writer's file written through a heredoc that mentions `gh` no longer stops the session. Text that a shell runs still counts as a command: `bash -c '...'`, `sh <<EOF`, input piped to `sh`, `eval`, `xargs`, and a command substitution such as `"$(gh pr merge 1)"` inside double quotes.
4. **Stops are caught when the builder first changes a file.** A builder's change to a lockfile, package manifest, settings file or protected path that the issue does not allow is now refused at once, with rule `stop`, when made with a file-editing tool, a Codex patch or a shell redirection. Other changes, such as `sed -i`, are still caught at merge, which keeps its check for every path. Before, one issue built and passed review for about 40 minutes before the merge refused it.
5. **`setup.py` counts as a manifest only at a package root:** at the repository root, or in a folder that also holds `pyproject.toml` or `setup.cfg`. A script named `setup.py` elsewhere, such as `scripts/setup.py`, no longer stops an issue.
6. **A finished build is never queued again in the same cycle.** A build that merged, parked or parked after a second crash could still show the `building` label in the loop's view for that cycle; it is no longer mistaken for an abandoned build.

## What was tested

All 880 tests in the kit's suite pass on macOS. Each change has tests that fail without it.

Not proven yet: the effect on a full run. The loop will finish its current work on this repository with 2.2.2, and that run is the measure.
