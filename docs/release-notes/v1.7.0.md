# AI Loop Kit 1.7.0

AI Loop Kit 1.7.0 makes walking away the default run. A run now walks away whenever the unattended checks pass, and a local dashboard lets you start runs, follow them and answer a builder's questions.

**Who gets what.** A run that used to be attended now walks away when the unattended checks pass. Those checks need, among other things, Claude Code 2.1.285 or later, 10 GB of free disk space and a `Sandbox domains:` line in `AGENTS.md`, and a piece that needs services keeps the run attended.

A walk-away run builds inside the sandbox, with network access limited to the domains you approved. It keeps your Mac awake, continues after you close Claude Code, and posts its summary to a GitHub issue titled "AI Loop Kit run log", which it creates if it does not exist. Add `--attended` to keep the previous behaviour.

The dashboard, builder questions and the other changes apply to every project. Notifications on macOS appear only if you turn them on in the dashboard. Waiting for blockers applies only to pieces that have a `Depends on:` line and are made ready after the update. The local test after a billing limit applies only with `Base merges: run`.

## Updating

1. Update the plugin, either from a terminal:

   ```text
   claude plugin update ai-loop-kit@ai-loop-kit
   ```

   or in Claude Code: run `/plugin`, open the **Installed** tab, select **ai-loop-kit** and choose **Update now**.

2. Run `/reload-plugins`, or start a new session, so Claude Code loads the new version.

No other action is needed. If you are updating from a version before 1.6.0, read the 1.6.0 notes first: they ask you to install uv. Your issues, pieces and loop settings stay as they are.

## What changes

1. **Walk-away is the default run.** A run starts as walk-away when the unattended checks pass. When a check fails, the run is attended instead and names the failed check and how to fix it. `--attended` chooses an attended run, and `--walk-away` refuses to start unless the checks pass. The run skill starts every run in its own session, with a log in `.loop/logs/`, so it continues after the Claude Code session that started it ends. The walk-away checks now accept a base branch with no tests when the first piece to be built is a scaffold piece.

2. **A live dashboard.** When Claude starts a run, it also starts a local server and gives you its address. The page shows every piece and the run as they change. You can tick ready pieces and start a walk-away run from it; if a walk-away check fails, the page refuses the run and lists each failed check with its fix. The server listens only on your computer. The address carries a token, which the page keeps in a cookie. The page cannot be read without the token, and every action also sends it in a header.

   Once a run has recorded events, `gate.py sync` also rewrites the static run page, `.loop/dashboard.html`, and the page shows when it was written.

3. **Builders can ask questions.** When a builder meets a choice it cannot settle, it hands the piece back with a question, usually with a recommendation: answer and retry when an answer is enough, or answer and reshape when the contract must change. The other pieces in the run carry on, and pieces that depend on the question wait.

   Answer on the dashboard or with `gate.py answer <n> --text "<answer>"`; add `--reshape` to send the piece back to shaping. Without `--reshape`, the piece goes through the ready checks again, and the next build attempt receives the question and the answer. Only answers from the repository's owner, members and collaborators are read.

4. **Notifications.** The dashboard reports when a piece is ready for review, handed back, rejected or asking a question, when a run finishes, and when a run appears to be stuck. On macOS, you can turn on system notifications as well.

5. **Pieces can wait for their blockers.** A piece whose `Depends on:` pieces are not done can now be made ready with its base check left pending. Until then, the checks that need the base wait, such as the check that the new test fails on the base, and the piece cannot be built. When the blockers are done, the run checks the piece against the base, and hands it back with the reason if that check refuses it. The aim is to let a new project be shaped in one sitting. This is not yet proven.

6. **Runs that keep going.** With `--keep-going`, a run also builds pieces that become ready, or come back to ready, while it works. Ask Claude to keep going when you start the run. An empty run no longer spends 20 seconds searching for ready pieces unless a piece became ready, or came back to ready, in the last five minutes.

7. **A handed-back piece is easier to pick up.** The dashboard shows the reason a piece came back and a command to copy, `claude "/ai-loop-kit:shape <n>"`. Shaping a returned piece starts from the latest reason it came back.

8. **Recovery and reliability.**
   - After a crash, the run finishes a piece that was already submitted instead of building it again. It does not repeat the review, and the pull request says so.
   - Calls to `gh`, and `git fetch` and `git push`, now stop with an error that names the call after 120 seconds instead of hanging.
   - With `Base merges: run`, when the run cannot merge a piece because GitHub did not run the checks for a billing or spending limit, the run tests the commit locally and reports the result on the piece's issue and in the run output.
   - The gate records the cost and token use of each builder attempt where the agent reports them.

9. **Judging.**
   - When the gate confirms that a new test fails for the right reason, only an assertion failure now counts. A test that fails because an option, module or argument is missing no longer passes this check.
   - The judge writer proves its judge against the base before it finishes, except while a blocker is not done.
   - The judge writer sees the Approach of the pieces a piece depends on.
   - The contract reviewer is told which reproducer file types can run.

## What we tested, and what is not proven yet

- All of the kit's own checks pass on Linux and macOS. Each change above has its own tests, named after the contract it meets.
- Not proven yet:
  - any of these changes on a real project;
  - a Claude walk-away run outside the kit's own tests;
  - the dashboard and macOS notifications with a real person and a real run;
  - a real builder question and answer;
  - a real GitHub billing limit.
