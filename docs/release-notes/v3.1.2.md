# v3.1.2

This release fixes the start check that 3.1.1 added for projects whose sessions use Codex. In 3.1.1 the loop ran the first test file it found inside the Codex sandbox and refused to start when the output reported a denied operation. A test that runs `ps`, or a test command that writes a cache outside the project, stopped the loop before it built anything, although merges run the tests outside the sandbox. In 3.1.2 the check asks only what every build needs from the sandbox.

Only projects with at least one Codex role are affected. Projects that use Claude for every role see no change.

## Updating

1. In Claude Code, refresh the marketplace, then update the plugin:

       /plugin marketplace update ai-loop-kit
       /plugin update ai-loop-kit@ai-loop-kit

2. Start a new Claude Code session so that the new plugin loads.
3. A loop that is already running keeps the version it started with. To move it to 3.1.2, stop it from the project root, wait until `.loop/loop.pid` is gone, and start it again:

       <plugin>/bin/loop stop
       mkdir -p .loop && nohup <plugin>/bin/loop run > .loop/loop.out 2>&1 &

This release needs no setup run and adds no setting.

If your Codex sessions run tests through a tool that keeps a cache in your home folder, such as `uv` with `~/.cache/uv`, the sandbox refuses to write there, and builders cannot run the tests themselves. List the folder in the `Codex writable roots` setting, for example in `loop.local.json`:

    "Codex writable roots": ["~/.cache/uv"]

## What changes

1. **The Codex start check no longer runs a project test.** At start, the loop now checks inside the Codex sandbox that the program named by the `Test files command` starts and that a file can be created and removed in the project folder. When either fails, the loop stops with a message that names the sandbox, as before. A project test that fails inside the sandbox because of a denied operation no longer stops the loop.

   On 24 November, 3.1.1 refused to start in two projects: in one, the first test file reached code that runs `ps`; in the other, `uv` could not write its cache.
2. **A refusal is judged by the command's own output.** The check used to add the word "sandbox" to the output before it looked for a denied operation, so any "Operation not permitted" counted as a sandbox refusal. It now needs both in the command's own output.

## What was tested

All 1209 tests in the kit's suite pass on macOS and Linux, in a fresh clone with the system's default temporary folder. New tests use a fake `codex` to check a program that starts, a program that is missing, a denied write in the project folder, and test output that reports a denied `ps`; one test now compares resolved paths, because the default temporary folder on macOS is reached through a link.

The loop on this repository started from this release's code and ran with every role on Codex. The check also passes against a second project that uses `uv`.
