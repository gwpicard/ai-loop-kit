# Person-synced reads before the App exists

The person may shape locally before installing the GitHub App. To read remote
dependencies and duplicates during that stage, the person runs the existing
sync command in a separate terminal: dry-run first, then its exact confirmation
digest. Agent sessions still cannot sync or use the person's credentials.

Confirmed sync checks the effective filesystem protection before any remote
write. It invalidates the old generation, sends the approved queue and collects
complete bounded issue, dependency and dropped-reason data. An empty queue can
refresh the reads. A failed refresh leaves no usable partial generation; remote
writes already sent are reported without claiming rollback.

The generation lives in the protected local loop settings. Its authority comes
from the filesystem sandbox and settings guards, not a hash of editable JSON.
The attended template blocks writes to the actual absolute project loop folder.
Setup, direct merging and pre-run share JSON root rendering. Unsafe exclusions,
local overrides and disabled filesystem protection refuse cache authority while
preserving the person's settings.

Readers check the project root, common Git directory, literal GitHub origin,
recorded repository ID, complete data and a maximum age of fifteen minutes.
Person sync checks the repository ID before and after collection. An offline
reader cannot discover later deletion and recreation at the same origin. This
is a point-in-time snapshot, not a promise that GitHub remains unchanged.

Without an App, ready uses the existing dependency graph checks on that complete
snapshot. Duplicate search includes uncaptured remote issues and names the
snapshot and its age. Missing or unusable snapshots refuse with person-sync
guidance. Installing the App restores live reads; an App failure never falls
back to cached data.

Collection refuses overflow or incomplete pagination. Limits are 500 catalogue
issues including raw pull-request entries, 500 dependency nodes, 5,000 edges,
500 comments per dropped issue, 8 MiB, thirty seconds per read and three minutes
for collection. Exact-full pages require a terminal-page check. Issue text is
inert data.

Synthetic checks prove configuration, validation and routing. The person must
separately check the installed filesystem sandbox: an opaque agent write must
fail while trusted setup and external person sync work. The builder does not
run a real Claude session to claim that result.
